学习前先看

这是基于 Tauri 官方文档整理的独立中文实践课程，不是 Tauri 官方课程。Vue 负责界面，Rust 负责原生业务，Tauri 连接两者。

当前只实现模拟通话，无真实 SIP 注册、呼叫或音频。前端构建与 6 项测试通过；云环境缺系统库，尚未完成原生构建和移动真机验证。

建议按顺序完成，每课做出一个可观察的结果。勾选进度仅保存到当前浏览器，不上传服务器。

LESSON 01

认识 Tauri：先分清三层

把 Tauri 想成一个装着网页的原生应用。Vue 写按钮和页面；Rust 处理本机逻辑；Tauri 把窗口、消息通信和打包连接起来。本课程先完成界面，不从框架源码读起。

本课官方文档 ↗

src/App.vue → 前端界面
src-tauri/src/lib.rs → Rust 命令与入口
src-tauri/tauri.conf.json → 窗口和构建配置

动手练习

打开在线演示，输入 1001，点击模拟呼叫再挂断。然后解释：哪部分是 Vue，哪部分将来应该放 Rust？

验收标准

能说明浏览器演示不会执行 Rust，也不会发出 SIP 呼叫。

LESSON 02

准备环境与第一次启动

先安装 Node.js 和 Rust，再安装系统依赖。Windows 需要 C++ Build Tools、WebView2 和 Rust MSVC；Linux 需要 GTK/WebKitGTK 开发库；macOS 需要 Xcode Command Line Tools。只有 Rust 还不能编译 Tauri 桌面程序。

本课官方文档 ↗

git clone https://github.com/penanegrarenea-ship-it/tauri-softphone-learning.git
cd tauri-softphone-learning
npm ci
npm run dev
# 原生依赖齐备后运行：
npm run tauri dev

动手练习

先运行网页，再运行桌面壳。不要在已有仓库里重复运行创建项目命令。若从零练习，可在另一个目录执行 npm create tauri-app@latest，选择 Vue + TypeScript。

验收标准

知道 npm run dev 是网页，npm run tauri dev 是原生应用。遇到 pkg-config / glib / webkit 缺失时，先查系统依赖。

LESSON 03

读懂项目结构

先看 package.json 的 scripts，再看 src/main.ts 如何挂载 App.vue。前端的 dist 是构建结果，不是源代码。Rust 的 Cargo.toml 声明依赖，lib.rs 放共享入口，main.rs 是桌面入口。

本课官方文档 ↗

src/App.vue              页面和模拟通话
src/style.css            桌面/移动布局
src/phone.ts             类型与纯函数
src-tauri/src/lib.rs     runtime_info 命令
src-tauri/capabilities/  能力范围

动手练习

修改页面标题，观察热更新；修改 tauri.conf.json 中窗口标题，再重启原生开发进程。

验收标准

能准确找到“改按钮”“改窗口”“加 Rust 方法”分别应该改哪里。

本例使用 idle、dialing、connected 三种模拟状态。点击呼叫先进入 dialing，1.2 秒后模拟接通，挂断回到 idle。计时和按钮不是网络协议；模拟扬声器也不会操作硬件。

本课官方文档 ↗

type CallState = 'idle' | 'dialing' | 'connected';
// 号码和时长工具函数在 src/phone.ts
// 页面状态与定时器在 src/App.vue

动手练习

将拨号盘提取成 DialPad.vue。用 props 接收号码，用 emit 通知父组件修改。检查空号码、重复点击、拨出后立即挂断以及切换导航。

验收标准

桌面能用侧栏，窄屏能用底部导航；挂断后不会被遗留计时器重新接通。

LESSON 05

前端调用 Rust：第一个 invoke

设置页的“检查运行环境”是最小通信示例。Rust 用 #[tauri::command] 标记命令，再用 invoke_handler 注册；前端使用 invoke 调用同名命令。普通浏览器没有 Tauri IPC，因此演示会明确提示。

本课官方文档 ↗

// src-tauri/src/lib.rs
#[tauri::command]
fn runtime_info() -> String {
    "Rust 通信正常".to_string()
}
// 注册：.invoke_handler(tauri::generate_handler![runtime_info])

// Vue / TypeScript
import { invoke } from '@tauri-apps/api/core';
const text = await invoke<string>('runtime_info');

动手练习

在 Rust 返回值加入“第一课完成”，在原生窗口点按钮验证。然后尝试拼错命令名，用 try/catch 显示可读错误。

验收标准

能解释 Promise/await、Rust 返回值和 invoke 的命令名如何对应。示例片段是教学简化版，不要覆盖整个入口文件。

LESSON 06

事件、安全与后续架构

按钮请求适合 command；未来来电、注册变化等主动通知适合事件。监听需在组件卸载时清理。不要把账号密码放进事件日志、localStorage 或公开仓库。Capabilities 与 CSP 应按最小范围配置，不要直接授予所有权限。

本课官方文档 ↗

// 未来练习，当前项目尚未接入真实事件
import { listen } from '@tauri-apps/api/event';
const unlisten = await listen<string>('phone-status', event => {
  console.log(event.payload); // 只放非敏感状态
});
// 组件卸载时执行 unlisten()

动手练习

先把模拟通话抽成 MockPhoneService，再定义 dial/hangup 和状态订阅接口。未来 Rust 实现替换 service，不让页面直接依赖 SIP 库。读官方 Capabilities 页面后，说明为什么不应开放任意 shell。

验收标准

能画出 Vue → PhoneService → Rust SIP 的结构，并知道当前代码还没有完成这一重构。

LESSON 07

移动端与“全端”的真实边界

同一套前端可以复用到 Windows、macOS、Linux、Android 和 iOS，但必须分别构建测试。Android 需要 SDK/NDK、JDK 等；iOS 需要 macOS + 完整 Xcode。GitHub Pages 只托管网页，不能运行 Rust 原生后端。

本课官方文档 ↗

npm run tauri android init
npm run tauri android dev
# 以下只能在 macOS + Xcode 上：
npm run tauri ios init
npm run tauri ios dev

动手练习

先在浏览器窄屏检查布局，再准备 Android 工具链。不要把响应式预览当成真机验收。以后 Web 真通话需要浏览器兼容的信令/媒体适配，原生 SIP 套接字不能原样搬进网页。

验收标准

能区分界面复用、原生构建和真实通话；知道移动后台来电与音频权限是单独课题。

LESSON 08

测试、打包与下一阶段

先把本阶段验收做完，再接真实 SIP。信令注册/INVITE 不等于双向音频：媒体采集、编解码、RTP/SRTP、NAT、权限和系统通话集成都要单独验证。不要把账号或测试服务器密码提交到 GitHub。

本课官方文档 ↗

npm test
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo check --manifest-path src-tauri/Cargo.toml
npm run tauri build

动手练习

完成一个小改动并新增测试，例如限制重复加号输入。打包前替换示例 identifier、图标，按目标平台准备签名。查看 VALIDATION.md，分清已通过与尚未验证的检查。

验收标准

第一阶段通过标准：四个页面可用、模拟流程可靠、理解 IPC、能在自己的目标平台启动原生窗口。
